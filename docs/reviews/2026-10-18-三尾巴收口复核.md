`d27f71b`（27 方法对齐）→ `ed858a7`（R03 迁移加固）→ `25a8c35`（R04）。

本批 R04 完整实现（全路径覆盖，上文 §二）曾以未提交状态存在于 main 工作区并验证通过，
中途一度被 stash（消息："R04 duplicate on main (superseded by feat 25a8c35)"）。复核判定：

- feat 侧 `25a8c35` 的 `immediate` 仅 2 处，覆盖面小于 main 工作区版的全路径事务化；

- 故 `git stash pop` 恢复 main 版（stash 基于 `51de4e8`，此后 kernel/tests 无新提交，恢复无冲突），
  恢复后定向回归全绿。

**合流建议**：SQLite 整体合流时，R04 以 main 全路径版为准，feat 的 `25a8c35` 被覆盖即可，
不需要单独合并。
