## 旅行场景与目标用户

**场景：学术田野调查旅行规划** —— 旅行规划的一个高门槛垂直场景。人类学、社会学等社科研究者需要赴异地长期驻村/驻社区开展田野工作（2 周至数月），这同时是一个复杂的旅行问题（大交通 + 长住住宿 + 目的地文化资源 + 有限经费）和一个研究设计问题（选点依据、调研节奏、访谈安排、风险评估），二者过去只能靠人工在多个平台间拼凑。作品覆盖目的地决策（田野点比选）、交通（航班/高铁方案对比）、酒店（按月租预算筛选民宿客栈）、目的地文化资源发现（宗教场所/古镇古村/博物馆/民俗活动）四类旅行子场景。

**用户**：社科类研究生与青年学者（主力，高频刚需：每学期开题/申报基金都要做田野方案）、导师课题组（多学生多点调研复用）、海外民族志研究者与留学生群体（申请海外/港澳项目的同时需要可核验的田野可行性方案）、NGO 及市场调研人员（访谈提纲与对象设计同样适用）、泛跨学科田野工作者（公共卫生、教育、建筑设计）。

## 我做了什么

**核心功能**：一个引导式访谈 Agent（“田野罗盘”），通过“研究定位 → 田野点画像 → 行程规划 → 方案生成 → 确认定稿”五阶段对话，基于经用户确认的身份与用途（海外/港澳申请、高校开题、基金申报、课程作业），利用飞猪实时搜索所得行程、住宿、预算、文化场所数据，把研究者简单的初步田野设想（如“研究西南少数民族村落宗族组织变迁，单人三个月，预算两万元”）转化为结构完整的研究方案（Research Proposal）草稿。

**飞猪 FlyAI 能力利用（8/8 全量接入，每项都重新定义用途）**：

| FlyAI 工具 | 田野语境下的用法 |
|---|---|
| `search-flight` | 国际田野大交通多方案对比（实测曼谷、加德满都航线可用） |
| `search-train` | 境内 + 港澳直通地面交通（实测深港火车通票） |
| `search-hotel` | 按“长期驻村”多策略筛民宿客栈：月租预算 × 网络办公需求 × 生活便利度（实测清迈民宿） |
| `search-poi` | 并行检索宗教场所/古镇古村/博物馆，构建当地文化资源图谱（实测加德满都中文讲解场所） |
| `search-keyword` | 补充检索非标准 POI 类目的边缘供给 |
| `ai-search` | 核心杀手锏：处理“从昆明出发、30 天、人均日预算 150 以内、要能网络办公”这类结构化工具无法表达的复合语义意图 |
| `search-marriott-hotel` / `search-marriott-package` | 有经费的课题组/机构接待场景的高标准住宿与套餐 |

不止“接入了 API”，而是把飞猪数据用出三层深度：

1. **时窗采样**：对同一路线做多日期价格采样 × 节庆覆盖 × 预算可行性，推荐调研出发窗口——把“查一次价”升级为对时间维度做实验；
2. **并行聚合**：一次提问并行扇出多类搜索（航班 × 酒店 × POI × 关键词，失败隔离），本地聚合为田野点画像、多段行程、末端接驳方案；
3. **证据链**：所有搜索经 RecordingClient 记录查询键与原始结果，预算与行程数字可溯源、可复核——对学术用户是刚需，也是“实时数据使用”的可验证形态。

工程侧同样围绕飞猪 API 设计：体验模式/自有 Key 双通道、搜索结果缓存复用（降低重复调用）、平台无村级供给时如实输出“枢纽城市方案 + 当地学术接待方进村安排”的二段式保障计划，不虚构供给。

**创新点**：

1. **把飞猪全品类搜索用在非消费场景**（见上表与三层深度）——通用行程产品服务“游客去玩”，本作品服务“研究者去工作”：同一个 8/8 工具面，产出的是选点依据、驻村成本、文化资源图谱与可执行的研究保障方案。
2. **不止旅行规划，还是研究设计辅助**：主题驱动的访谈对象生成器——大模型依据用户的研究设计动态列出候选访谈对象（每类含接近策略、提问域、伦理注意事项，敏感议题下伦理字段为强制项），人工精选的示范档案库仅作写法质量锚与降级兜底，最终名单由用户决定；并可生成半结构式访谈提纲与知情同意书草稿，嵌入提案方法论章节——这是通用行程规划产品完全没有的学术纵深。
3. **行程即保障：田野工作支持方案**：阶段推进由可验证条件判定（必填信息齐备、田野点确认、访谈对象登记、方案确认），而非模型自由发挥；调研节奏（适应/深入/补充期）、缓冲日、备选路线、食宿与通讯可达性构成可执行的田野保障方案；非访谈型研究可显式跳过访谈环节，流程不强行套模板。
4. **MCP 内核化架构**：旅行搜索与研究设计能力封装为标准 MCP Server（32 个 tools：23 项内核能力 + 9 项状态工具，另有 guidance/模板/项目级资源面与 2 个 prompts），任何 Agent 宿主（如千问办公、百炼 Managed Agents）皆可复用整套田野旅行规划能力，Web 界面只是其中一个展示宿主——工具 schema 单一来源、三宿主（CLI/Web/MCP）共用，能力沉淀到协议层而非锁死在单个应用里。

**解决的具体问题**：社科实地调研田野点选择依据缺乏数据支撑、长期驻村住宿与经费难以核算、行程与研究节奏脱节、研究方案写作碎片化。过去一名研究生需要 1-2 周完成的调研筹备文档，现在几轮对话即可产出初稿。

**后续商品化规划**：海内外各大高校开题/国社科/各省哲社科体例（以 skill 形式提供）、RAG 学术知识库、海外地理 provider、完善的账号体系+长期记忆、钉钉导出能力等。

## 百炼使用说明（必填）

- **百炼能力 / 模型**：通义千问 **qwen3.8-flash**（访谈主持与 function calling 工具决策，高频对话环节）+ **qwen-max**（研究方案与访谈提纲生成，长文质量敏感环节）。百炼位于**运行时链路**：Agent 与用户的每一轮对话、每一次工具编排决策、每一份提案生成都在线调用百炼完成；同时用于开发链路（代码生成与测试用例辅助编写）。
- **调用方式（百炼 API / DashScope SDK / 百炼 CLI `bl` / OpenWork）**：DashScope SDK（`Generation`）为主；function calling 走 OpenAI 兼容端点 `/compatible-mode/v1/chat/completions`，套餐 Key 可切换专属兼容端点（httpx 直连）。模型按用途分三档配置（访谈/生成/信息提取），env 可切换。
- **使用环节与输入输出**：
  - 环节 1 访谈推进：输入=用户消息 + 项目状态快照 + FlyAI 工具 JSON Schema → 输出=回复文本 + tool_calls（决定调用哪些飞猪搜索及参数）；
  - 环节 2 结果解读：输入=归一化搜索结果（航班/住宿/POI 列表） → 输出=面向研究者的画像分析文本；
  - 环节 3 方案生成：输入=结构化田野点画像 + 行程方案 + 访谈对象清单 + 知识库条目 → 输出=八章 Markdown Research Proposal；
  - 环节 4 访谈提纲生成：输入=研究主题 + 访谈对象类型 → 输出=各类型半结构式提纲（含知情同意话术）。
- **Skill 名称（如有）**：`flyai-skill`（`npx skills add alibaba-flyai/flyai-skill`，提供 flyai CLI 的 8 个旅行搜索工具）。
- **其他工具 / 技术栈**：Qoder CN IDE、千问办公、Python 3.12 + pydantic、prompt_toolkit（CLI 宿主）、FastAPI + SSE + React/Vite（Web 宿主与展示界面）、`mcp` Python SDK（MCP Server）、FlyAI CLI（subprocess 调用）、pytest 全 mock 测试 + GitHub Actions 双平台 CI、JSON/SQLite 双存储后端（可迁移）。辅助数据源：高德 Web 服务 API 6 原语用于末端接驳与周边设施，OpenAlex 用于提案文献线索检索。
